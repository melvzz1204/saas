Contrast policy (WCAG 2.1 AA): body text uses --text-2 (≥ 7:1); interactive accents use --accent (≥ 4.5:1); --text-3 is reserved for 14px+ bold meta and never for paragraphs. Accent fills always carry --accent-ink text.

Motion policy

Micro-interactions are limited to transform/opacity only (GPU-cheap, no layout thrash): button lift on hover/active, card lift with border glow, floating mockup chips (6–7s), pulse dots, and one-shot scroll-reveal via .reveal → .visible. A global @media (prefers-reduced-motion: reduce) rule zeroes every animation and transition and force-reveals content, and the reveal observer is never attached for reduced-motion users. 

<!-- Add to any element to fade it in on scroll -->
<div class="reveal">…</div>
<!-- landing.js adds .visible when it enters the viewport -->

10 · Toast notifications window.Toast — global success/error feedback

Trigger examples (live)

Toasts float near the bottom of the viewport, auto-dismiss after 5s (errors 7s), pause on hover, and stack newest-last. Loaded on every page via /src/util/toast.js.

11 · Implementation checklist

  1. Tokens first: define :root custom properties exactly as in landing.css §1 — colors, type scale, spacing, radii, shadows.
  2. Fonts: load Plus Jakarta Sans 400–800 with preconnect + display=swap.
  3. No framework required: the system is plain CSS. If Tailwind is present, treat tokens as the palette source and avoid hardcoded colors.
  4. Accessibility: one <h1> per page, landmarks, skip link, visible :focus-visible rings, 44px targets, labels on every input, and semantic <details> for FAQ.
  5. Performance: no runtime CSS compilation, no hero raster images (mockups are CSS), defer scripts, IntersectionObserver guarded by prefers-reduced-motion.
